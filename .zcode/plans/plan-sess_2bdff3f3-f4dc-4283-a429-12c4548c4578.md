Target project: **ps** (`/home/alex/Documents/GitHub/ps` — arten-fördern.app), not the apf2 repo this session started in. apf2 already got this fix on Nov 8 (`1b233f743 perf: map layers with all arts load without blocking the UI`); ps is the sibling app where apf2 features are being ported to (its history mirrors apf2 commit-by-commit), and it's the only other project with a react-leaflet map.

## Problem in ps

All three marker-rendering paths build **every leaflet layer synchronously in one commit** via react-leaflet's `<GeoJSON>` (which constructs all layers in `L.geoJSON()`'s constructor and ignores later `data` changes — ps works around that with `key`-remounts):

- `src/components/Map/layers/TableLayers/TableLayer.tsx:150` — table layers (observations/places/checks/actions), **no LIMIT**, and creates 2–3 leaflet objects per point (`L.LayerGroup` of invisible clickable `L.CircleMarker` + visual marker; `DivIcon` markup via `ReactDOMServer.renderToString` per point)
- `src/components/Map/layers/VectorLayer/WFS.tsx:312` — WFS vector layers, unbounded GetFeature response
- `src/components/Map/layers/VectorLayer/PVLGeom.tsx:200` — local vector-layer geometries (capped at `max_features`, default 1000; also binds a `renderToString` popup per feature). Currently unreachable (`VectorLayerChooser` hardcodes `geomCount = 0`) but same pattern.

With high marker counts the whole build lands on the main thread at once and freezes the UI. (ps has no permanent label tooltips, so apf2's tooltip fix doesn't apply — only the chunked-mounting part is ported.)

## Approach — one imperative progressive L.GeoJSON layer

apf2 chunked React-mounted `<Marker>`s (300 per animation frame, cached elements appended). ps's equivalent for `L.geoJSON` is **one stable layer instance, filled imperatively with `addData()` in chunks per animation frame** — each chunk then only builds its own markers, nothing reconciles predecessors.

**New `src/components/Map/layers/progressiveGeoJSON.ts`** (pure, leaflet-free, unit-testable):
- `flattenGeoJSON(data: GeoJsonObject | GeoJsonObject[] | null): Feature[]` — flattens whatever the three call sites pass today (single FC, array of FCs, bare features; Leaflet's `addData` accepts arrays recursively, this mirrors that)
- `addProgressively(features, addChunk, { chunkSize = 300, budgetMs = 12 }): () => void` — calls `addChunk(slice)` per animation frame, up to `chunkSize` features but never longer than ~12 ms per frame (ps markers are heavier than apf2's — 2–3 leaflet objects + renderToString each); returns a cancel function. `requestAnimationFrame` injected/defaulted so tests can drive it with a fake.

**New `src/components/Map/layers/ProgressiveGeoJSON.tsx`** (drop-in replacement for `<GeoJSON>`):
- Props: `{ data, resetKey, options, chunkSize? }` where `options` is the exact object react-leaflet used to spread into `new L.geoJSON(data, options)` (`pointToLayer`, `style`, `onEachFeature`, `geomanIgnore`, `opacity`, …)
- Uses `useLeafletContext()`; creates `L.geoJSON(undefined, { ...options, pane: context.pane })`, adds to `context.layerContainer ?? context.map` (replicates react-leaflet's `withPane` + `useLayerLifecycle`, so layers still render into the per-layer `<Pane>` from `Layer.tsx` with its z-index)
- `resetKey` change → recreate layer with fresh options (replaces today's `key`-remount semantics; the existing key strings move over unchanged)
- `data` identity change → `clearLayers()` + restart progressive fill
- unmount → cancel rAF + remove layer; zoom gating stays as-is (components still return null outside min/max zoom)

**Call-site changes** (mechanical): `TableLayer.tsx`, `WFS.tsx`, `PVLGeom.tsx` swap `<GeoJSON key=… data=… …props>` for `<ProgressiveGeoJSON resetKey=<old key string> data=… options={{…old props}} />`; behavior (styling, activeId highlight, drag/assign handlers, popup binding) is untouched — same factories, just invoked per chunk.
